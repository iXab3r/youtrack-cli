# Local policy provenance and ownership

## Authority and updates

These are locally owned, binding product instructions. The owner's explicit decision authorizes
copying/adapting shared instruction text so this repository can be read offline. Required guides
are local; external links in this repository are optional provenance or API/reference citations,
never a missing policy body or prerequisite reading. The product's own release.md governs release.
Instruction updates are manual, intentional and reviewed, independently of runtime dependency
upgrades. There is no cross-repository auto-sync or requirement to compare against upstream online.
This repository may intentionally diverge in policy under an explicit owner decision, recorded with
scope/reason/evidence. Shared API behavior must still match the actual exact Core dependency.

## Exceptions and reference boundaries

The only deliberate policy ownership exception is the owner's authorization of local instruction
copies/manual updates instead of remote canonical reading. Runtime invariants, privacy, permission,
independent review, story planning and owner release/service gates are preserved. Neither setup
adoption nor copying a role authorizes spawning agents or publishing inventory/stories/releases.
No new service compatibility/version policy or generator is invented. Existing shipped commands
and deferred backlog remain the baseline. Remote API/source links may explain historical/public
interfaces, but all applicable binding instructions are present locally.
